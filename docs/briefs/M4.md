## Goal

Elijah can talk to Falak by DM'ing a Discord bot from his phone or Mac, with the same brain, apps and
confirmations as `jarvis chat`. To get there, M4 adds:
- a **channel interface**, so every way of talking to Falak plugs in the same way (Discord now, the desk
  and the iPhone later)
- a long-running **host process**, `jarvis serve`, that hosts the channels

app is ported (M7) or at cutover (M9), whichever comes first. Don't add a Telegram channel in M4.

## Elijah's setup (he does this; you never handle the token)

1. At discord.com/developers/applications: **New Application**, named "Falak". On the **Bot** tab:
   - **Reset Token** and copy it.
   - Turn **Public Bot** off.
   - Leave **Message Content Intent** off. DMs to the bot include their content without it.
2. In `~/Library/Application Support/Falak-dev/.env`, add the line `DISCORD_BOT_TOKEN=<token>` himself.
3. Create a private Discord server, just him (M8 adds a voice channel there).
4. Invite the bot:
   - In **OAuth2 → URL Generator**, pick scope `bot` and the permissions Send Messages and Read Message
     History.
   - Open the URL and choose the server.
5. Turn on Discord **Developer Mode** (Settings → Advanced). Right-click his own name → **Copy User ID**.
   Add this to `Falak-dev/settings.toml`:
   ```toml
   [channels.discord]
   owner_id = 123456789012345678
   ```

If the token or `owner_id` is missing, `jarvis serve` skips Discord with one plain line saying what's
missing, and doesn't crash.

## 1. The channel interface: `jarvis/core/channel.py`

```python
@dataclass(frozen=True)
class Incoming:
    channel: str                    # "discord", "cli", ...
    text: str
    attachments: tuple[Attachment, ...] = ()   # files Elijah sent, saved in the core tmp folder
    reply_to: object = None         # adapter-specific handle (e.g. the Discord DM), opaque to the core

class Channel(Protocol):
    name: str
    async def start(self, deliver: Callable[[Incoming], Awaitable[None]]) -> None: ...  # runs until stopped
    async def stop(self) -> None: ...
    async def send(self, text: str, *, reply_to: object = None, ask_id: int | None = None) -> None: ...
    def typing(self, reply_to: object) -> AsyncContextManager[None]: ...  # "Falak is typing…" while a turn runs
```

- **Only Elijah's messages are delivered.** Each adapter drops anything not from him before it reaches the
  core. That means every delivered message is from an own channel.
  - Replace M3's hard-coded `OWN_CHANNELS` in `tools.py`. The host builds that set from the channels it
    started, plus `cli`, and passes it into the turn.
  - The core still never names a specific channel.

## 2. Where the code lives

- `jarvis/channels/<name>.py` holds adapters, starting with `discord.py`. They may import
  `jarvis.core.channel`, `jarvis.core.api` (`Attachment`) and `jarvis.protocol`, and nothing else from the
  core.
- `jarvis/host.py` is the composition root. It loads settings, apps and the brain, starts the enabled
  channels, and routes each `Incoming` to `loop.handle_message`.
- Update `ARCHITECTURE.md`'s layout and rule 3, and add `tests/test_layout.py` checks:
  - `jarvis.core` never imports `jarvis.channels` or `jarvis.host`
  - channels import only the modules listed above
  - only `jarvis/channels/discord.py` imports `discord`
- Move `chat_cli.py`'s turn handling onto the same host routing. `jarvis chat` stays a terminal channel,
  so there's one path for every channel.

## 3. The host: `jarvis serve`

- One asyncio event loop. Start every enabled channel (settings `[channels.<name>]`, `enabled` defaults to
  true when the channel's secrets exist).
- **One turn at a time.** Incoming messages go on a queue that a single worker runs in order, which keeps
  M3's one-thread SQLite assumption true.
  - If messages arrive while a turn runs, they're handled in order afterwards. (Interrupting a turn comes
    later.)
- While a turn runs, show the channel's typing indicator.
- **Replies go back** through the channel the message came from, with `reply_to`.
  - If the turn created a new pending ask, pass its `ask_id` to `send()` so the channel can show Yes/No
    buttons. `loop.Reply` should say which asks the turn created.
- **Clean shutdown on Ctrl-C:** stop the channels, let the running turn finish or hit its timeout, close the
  registry.
- **Logging:** one line per turn (channel, ms, tools, error). Never log message text at INFO.
- **Core settings:** add `channels: dict[str, dict]` to `Settings`, with the same strictness as `apps`.
  - Each channel declares its known keys and types in its module.
  - An unknown key is a `SettingsError` naming the channel.
  - A section for a channel that doesn't exist is a warning, like M3's app warning.

## 4. The Discord adapter: `jarvis/channels/discord.py`

**Dependency:** add `discord.py>=2.7,<3`, with the reason in its own commit.

**Connecting:**
- Use `discord.Client` with minimal intents (`Intents.none()` plus `dm_messages`). Add others only if DMs
  don't arrive without them, and report which.
- The token comes from the core's secrets loader (`DISCORD_BOT_TOKEN`). Never log it, and never print it in
  errors.

**Incoming:**
- Handle **DMs only**, and only when `message.author.id == owner_id`. Everything else is ignored silently:
  other people, servers, other bots, and the bot itself.
- **Image attachments** from Elijah (png, jpg, gif, webp; ≤10 MB each):
  - Download them into the core tmp folder and put them in `Incoming.attachments`.
  - The turn prompt mentions them ("Elijah attached 1 image"), and a core tool shows them (section 5).
  - Other attachment types get a short note in the prompt ("Elijah attached report.pdf, which you can't
    open yet").
  - Voice messages get "Elijah sent a voice message; you can't listen to those yet".

**Outgoing:**
- Split long replies at paragraph or sentence boundaries into ≤2,000-character messages.
- Plain text; Discord's markdown is fine as it is.
- Discord rate limits are handled by `discord.py`. Don't add your own retry loops.

**Ask buttons:**
- When `send()` gets an `ask_id`, attach **Yes** and **No** buttons (a `discord.ui.View`).
- A press is accepted only from `owner_id`. It calls the same core function the loop uses to answer asks,
  `actions.answer_ask`, through a small host callback so the adapter doesn't import `actions`.
- Acknowledge the interaction right away, then edit the message to show the outcome ("Sent." / "Okay, I
  won't."), and disable the buttons.
- A press on an ask that's no longer pending says so.
- Typing "yes" in the DM still works through the loop, as in M3. Buttons are only a shortcut.
- Buttons don't need to survive a restart. After a restart the text answer still works.

**Typing indicator:** use `channel.typing()` while the turn runs.

**Connection loss:** `discord.py` reconnects on its own. Log disconnects at WARNING and reconnects at INFO.

## 5. Images Elijah sends

- Add a core tool, `falak__view_attachment(n)`, that returns the nth image of the **current** message as an
  image block. It's for when Falak needs to look ("what's this error?").
  - Viewing counts as outside content for the rest of the turn, the same as `untrusted_output`, because a
    screenshot can carry someone else's words.
- Attachments are deleted when the turn ends, whether or not they were viewed. Photos are never kept.
