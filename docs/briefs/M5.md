# M5: The Mac node and live views

**For:** Claude Sonnet, building in Claude Code, in the `~/Developer/falak` worktree on branch `rehaul`.
**Read first:** `CLAUDE.md`, `ARCHITECTURE.md`, then "Architecture", "Tools are apps" and "Senses are
tools" in `PLAN.md`. Build on M2's `actions.py` and the M4 host; don't route around them.

## Goal

Split the Mac's device side into its own process, the **Mac node**, which talks to the host over a local
WebSocket. Device apps run on the node. Everything that decides (validation, confirmations, logging, asks)
stays on the host.

Then add **live views**:
- "Pull up homework view" opens a camera session (the webcam, or the iPhone's Desk View camera).
- Falak can look at the current frame whenever it needs to, across turns, until the view is closed.
- The same works for the screen, and a `screen` app gives single screenshots too.

This is the shape every later device uses (iPhone, Watch, glasses), so the protocol and routing matter more
than the number of features.

## Out of scope

Leave these for later and note anything you needed from them:
- the recorder and mic, which need Whisper and move to M8
- clicking and typing on screen
- Falak watching a view on its own and speaking up when something changes (that needs the scheduler and
  events, M6+); in M5 Falak looks when a turn asks
- Tailscale and other machines: M5 binds to `127.0.0.1` only, though the protocol must not assume localhost
- a launchd job for the node (M9)
- any new UI beyond the optional preview window in section 6

## 0. A shared contract package (do this first, as its own commit)

The node has to read manifests and call handlers, but rule 3 forbids the node importing the core. So move
the app contract into a new package both sides use:
- `jarvis/core/api.py` → `jarvis/contract/api.py`
- `jarvis/core/manifest.py` → `jarvis/contract/manifest.py`
- `jarvis/core/schema.py` → `jarvis/contract/schema.py`

Update every import, with no re-export shims, so there's still one way. Then update rule 3 in
`ARCHITECTURE.md` and the layout tests:
- `contract` imports nothing else from `jarvis`.
- `apps` import only `jarvis.contract.api`, `jarvis.protocol` and their own folder.
- `core`, `node` and `channels` may import `contract` and `protocol`.
- `core` and `node` still never import each other.

## 1. The protocol: `jarvis/protocol/`

JSON text frames over WebSocket. Dataclasses with `to_json` and `from_json`, and a `type` field on every
message. Version it from the start: `"v": 1`.

| Message | Direction | Fields |
|---|---|---|
| `hello` | node → host | `node` (name), `key`, `capabilities` (list), `apps` (names it can run), `v` |
| `welcome` | host → node | `node_id`, `settings` (per app it runs, already merged and validated by the host) |
| `reject` | host → node | `reason`, then the host closes |
| `call` | host → node | `id`, `app`, `handler`, `args` (already validated), `timeout_s` |
| `result` | node → host | `id`, `ok`, `text`, `data`, `undo`, `subject`, `attachments` (base64 + mime, ≤10 MB total), `error` (an `ActionError` message), `crash` (true for other exceptions) |
| `ping` / `pong` | both | `t`. The host pings every 20 s and drops a node silent for 60 s. |

- Unknown types and malformed frames get logged and dropped. They never crash either side.
- The protocol package stays dependency-free. The WebSocket library is used only in the host and node
  transport modules.

**Dependency:** `websockets>=15,<16`, for both the server and the client, in its own commit with the reason.
It's small and pure Python.

## 2. Pairing and identity

- `jarvis node pair <name>` (run on the host):
  - creates a random key
  - stores only its SHA-256 in a new core table, `nodes(id, name, key_hash, created_at, last_seen,
    revoked_at)` (migration `0004`)
  - prints the key **once**
- `jarvis node revoke <name>` and `jarvis node list`.
- The node keeps its own config in **`FALAK_NODE_DIR`** (default `~/Library/Application Support/Falak-node/`),
  separate from the host's data folder even on the same Mac, because that's how every other device will
  work. It holds:
  - `.env` with `FALAK_NODE_KEY=…`
  - `node.toml` with `name` and `host_url` (default `ws://127.0.0.1:8765`)
  - its own `tmp/`
- The node never opens the host database.
- The host rejects a `hello` with an unknown, revoked or wrong key, or a version it doesn't speak. One node
  connection per name: a new connection with the same name replaces the old one.

## 3. Routing on the host

- `jarvis serve` also runs the node server, at a core setting `node_listen = "127.0.0.1:8765"`.
- Replace M2's `run_on_this_machine()` with a router:
  - `runs_on = "host"` → run in-process, as now.
  - `runs_on = "node:<cap>"` → send a `call` to a connected node that has `<cap>` and runs that app, then
    await the `result`.
    - Prefer the node Elijah is at. Presence comes later, so for now take the most recently connected one.
    - If there's no such node: `Failed("That needs <cap>, and no device with it is connected.")`.
    - On a timeout: `Failed` naming the node and the wait.
    - If the node drops mid-call: `Failed` saying the device disconnected.
- Everything else in `actions.run` stays on the host, unchanged: input validation, the confirmation policy,
  asks, the action log, undo and attachment handling.
  - Attachments from a node are written into the host's tmp folder and become normal `Attachment`s, so
    release and sweeping work as in M2.
  - Undo for node apps: the undo handler runs on the node through the same call path.
- **Context for node apps:**
  - `AppContext.db` isn't available on a node: accessing it raises a clear error.
  - Node apps get their settings from `welcome` and their secrets from the node's own `.env`, limited to
    what the manifest lists.
  - App context handlers (`[app] context`) for node apps run on the host only if the app is also on the
    host. Otherwise skip them in M5.
- `jarvis nodes` lists connected nodes with their capabilities. `jarvis dev info` shows the count.

## 4. The node process: `jarvis node run`

- Loads only the apps whose `runs_on` is `node:*`, using `jarvis.contract.manifest`. It advertises their
  capabilities and names in `hello`.
- Runs each `call` in a worker thread with its timeout, so a slow camera doesn't block pings, and sends
  the `result`.
  - Each node handler runs in one thread at a time.
  - Attachment files on the node are deleted once they've been sent.
- **Reconnects** with backoff (1, 2, 5, 10, then every 30 s) and logs each state change once.
- Ctrl-C closes cleanly.
- The node writes its own JSON log at `FALAK_NODE_DIR/logs/node.log`, using the same formatter (factor it
  into `contract` or keep a small copy in `node`, whichever keeps the layout rules simple).

**Development convenience:** `jarvis serve --with-node` starts a node process as a **child process**, so
there's one command while developing. It's still a separate process over the WebSocket, not in-process.
- If the node has no key yet, `--with-node` pairs one automatically for the name `mac`.

## 5. Sessions (live views) in the manifest

Add `[[sessions]]` to the manifest. This replaces M2's "`sessions` is not valid yet" error.

```toml
[[sessions]]
name = "live_view"
description = "Open a live camera view so you can look at what Elijah is showing you, as often as you need, until it's closed."
effect = "read"
untrusted_output = true
idle_minutes = 15                 # closes itself after this long without a look
start = "start_live"              # handler(ctx, **input) -> SessionStarted(text, state: dict)
sample = "sample_live"            # handler(ctx, state) -> Result (usually one image attachment)
stop = "stop_live"                # handler(ctx, state) -> Result
[sessions.input]
type = "object"
properties = { device = { type = "string", description = "Camera name, e.g. 'Desk View'. Leave out for the default." } }
additionalProperties = false
```

- The core gives each session three tools:
  - `<app>__<session>_start(input)` returns the session id and the first frame
  - `<app>__<session>_look(session_id)` returns the current frame
  - `<app>__<session>_stop(session_id)`
- **The host keeps the session table**, `sessions(id, app, name, node_id, state_json, started_at,
  last_look_at, stopped_at, stop_reason)` in migration `0004`. The node keeps the live resources (the
  running capture process).
- A session stops when:
  - the model calls `_stop`
  - Elijah says "close homework view", which is the model calling `_stop`
  - it's been idle longer than `idle_minutes`; the host checks on every turn and every 30 s
  - its node disconnects
  - `jarvis serve` exits

  Record the reason each time.
- The turn context lists open sessions ("camera live view #3, open 4 min, last look 1 min ago"), so "what
  about now?" works in a later turn.
- Looks go through the same policy and log as actions: `read` runs, and `untrusted_output` flips the turn's
  origin.
- The contract tests cover sessions: handlers exist, the effect is valid, and `idle_minutes` is 1–120.

## 6. The apps

**camera** (move it to the node, with `runs_on = "node:camera"` as before):
- Keep `take_photo`.
- Add the `live_view` session. `start` runs **ffmpeg** (installed at `/opt/homebrew/bin/ffmpeg`), reading the
  avfoundation camera into a single file that's continually overwritten at about 2 fps, scaled to ≤1280 px
  wide. `sample` copies the latest frame into a temp attachment, and `stop` kills ffmpeg and removes the
  frame file.
- **Choosing the device:**
  - Match the `device` input or setting against `ffmpeg -f avfoundation -list_devices true -i ""` by
    case-insensitive substring.
  - On Elijah's Mac the devices include "MacBook Neo Camera" and "<iPhone> Desk View Camera", so "desk view"
    picks the iPhone's top-down view (Continuity Camera).
  - If there's no match, the error lists the available camera names.
- **Optional preview** (a setting, `preview = true` by default): start `ffplay` on the same device in a small
  window titled "Falak: live view", and close it with the session. This is a stand-in until the UI overhaul.
  If the preview fails, the session still runs.
- Errors as in M2: permission (which app needs Camera access), device busy or missing, ffmpeg missing.

**screen** (new, `runs_on = "node:screen"`):
- `look()`, effect `read`, `untrusted_output`, `log_args = false`. It takes one screenshot of the whole
  screen with `screencapture -x -t jpg` into a temp file, scaled to ≤1600 px wide.
- A `live_view` session that does the same on each look. It doesn't need a background process; just capture
  on `sample`.
- **Exclusions:**
  - Before every capture, check the frontmost app and its window title. Port `excluded()`, `EXCLUDED_APPS`
    and `EXCLUDED_TITLE_WORDS` from `legacy/jarvis/screen.py`, plus extra words from a setting.
  - If excluded, take no picture and return a plain `Result`: "Your screen shows a banking or password app,
    so I didn't look." That's a result, not an error.
  - Use `pyobjc-framework-Quartz` for the window list (add it in its own commit with the reason) and port
    `front_window()`. If the window can't be read, don't capture.
- Errors: Screen Recording permission missing (say which app needs it), a locked screen (port `locked()`).

Both apps get tests with the subprocesses mocked. Never open the real camera or screen in tests.

## 7. Tests

- **Protocol:** every message round-trips; unknown and malformed frames are dropped; version mismatch.
- **Pairing:** keys are stored only as hashes; wrong, unknown and revoked keys are rejected; a reconnect with
  the same name replaces the old connection.
- **Host and node over a real localhost WebSocket in tests** (an ephemeral port; no outside network):
  - a call round-trips with an attachment, which lands in the host tmp and is released after the turn
  - an `ActionError` comes back as `Failed` with its message
  - a crash comes back as `Failed` with the generic message
  - a timeout
  - the node dropping mid-call
  - no node with the capability
  - reconnect after the host restarts
  - ping timeout drops a silent node
- **Routing:** host apps still run in-process; node apps never run on the host.
- **Sessions:**
  - start, look and stop
  - idle stop
  - stopping on node disconnect
  - open sessions in the turn context
  - a look flips outside content
  - the session tools are named and generated correctly
  - Use a fake capture backend.
- **Screen exclusions:** excluded apps and titles return the "didn't look" result and never call
  `screencapture`.
- The layout tests for the contract package, and every earlier test, still pass.
