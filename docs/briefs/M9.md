# M9: Voice

**For:** Claude Sonnet, building in Claude Code, in the `~/Developer/falak` worktree on branch `rehaul`.
**Read first:** `CLAUDE.md`, `ARCHITECTURE.md`, then "Message channels" in `PLAN.md`. Build on the M4 channels, the
M5 node and M8's `ctx.notify`. Don't add a second agent loop, a second permission check or a second way to send
messages.

## Why this milestone is about feel

The old JARVIS's voice is the part Elijah hated most. It read out exactly what it would have texted (whole
commands, errors, links), it couldn't be interrupted, and every exchange was prompt, wait, answer. M9 is done when
talking to Falak feels like talking to someone:

- **Speech isn't text.** A spoken reply is short and said the way a person would say it. Details (commands,
  errors, code, links, lists) go to Discord, and Falak says so: "I've put the full error in Discord."
- **Elijah can interrupt.** When he starts talking, Falak stops within a fraction of a second, on speakers as well
  as headphones.
- **It keeps the conversation going.** After the first "Hey Falak", follow-ups need no wake word. Falak starts
  speaking its first sentence while the rest is still being written, and says a few words ("one sec, checking")
  before anything slow, instead of going silent.
- **The voice is Elijah's to change.** "Make your voice deeper and a bit older" changes it at once, and "undo that"
  changes it back.
- "Sir" stays.

## Decided (Elijah, 2026-10-28)

- **Where things run.** The host does the voice work: speech-to-text, the turn, the spoken reply and the voice
  itself. The node does the desk: mic, speakers, echo cancellation, the wake word, the push-to-talk key,
  detecting that Elijah is talking, and stopping playback. The same host voice serves the desk and Discord calls,
  and it moves to the Mac mini with the host.
- **The voice model.** OmniVoice (`k2-fsa/OmniVoice`, Apache-2.0), the engine behind the VoiceStudio app in the reel
  Elijah sent, **if it fits this Mac** (section 1). The voice is **designed from attributes** (gender, age, pitch,
  accent, whisper), not cloned from a recording. Use OmniVoice directly, not the VoiceStudio app (AGPL, and far
  more than Falak needs).
- **Starting a conversation:** "Hey Falak", a push-to-talk key, and follow-ups without the wake word.
- **Discord voice calls are in M9**, as part 2, after the desk works.
- **Stand-in voice:** Kokoro (`kokoro-82m`, British male), already downloaded for the old JARVIS. The engine is
  swappable, so OmniVoice can arrive with the Mac mini if it doesn't fit now.

## Constraints

- **8 GB of RAM** shared with Claude Code, a browser and Falak. Disk had **6.6 GB free** on 2026-10-28; OmniVoice is
  ~3.3 GB. Check free space before any download and stop if it would leave less than 2 GB.
- The old JARVIS's models in `~/Library/Application Support/JARVIS/models/` (Kokoro, Whisper `base.en`) may be
  **read** (copied or loaded by path); never write there.
- Nothing is recorded to disk. Audio lives in memory and is dropped after it's transcribed or played.
- Nothing is transcribed unless the wake word, the push-to-talk key or a follow-up window started it.
- New dependencies are allowed in this milestone with a reason in the commit: the TTS and STT engines, a wake-word
  engine, a VAD, and `@discordjs/voice` for part 2. Keep the node light.

## 1. Speech engines (host)

- A new top-level package `jarvis/speech/`: engines only, no knowledge of channels, apps or the core. It imports
  nothing else from `jarvis`. Update the layout rules and `tests/test_layout.py`: channels and `host.py` may
  import it; the core may not.
- `Listener.transcribe(pcm16: bytes, rate: int) -> str`.
- `Voice.synthesize(sentence: str, profile: VoiceProfile) -> bytes` (PCM16 at a fixed rate), with engines
  `omnivoice`, `kokoro` and `say` (macOS `say`, the last resort). One engine is loaded at a time, kept warm,
  unloaded after `voice_idle_minutes` (default 30) and loaded again in the background when a conversation starts.
- `VoiceProfile`: the OmniVoice attributes, or Kokoro's voice name (Kokoro can blend two voices; use that for
  "deeper" and "warmer" on Kokoro) and speed.
- `sentences(stream) -> Iterator[str]`: cuts streaming text into sayable sentences. Port the splitter from
  `legacy/jarvis/speech.py`, and never cut inside a number, an abbreviation or a quoted name.

## 2. The voice profile (host app `voice`)

- `voice_profiles` table: the current profile and its history.
- **set_voice(attributes)**, local, with undo. It validates attributes against what the engine supports (OmniVoice:
  gender, age, pitch, the `whisper` style, English accent), and answers with what changed. If the request can't be
  done on the current engine ("give it a French accent" on Kokoro), it says what's possible instead.
- **current_voice()**, read, `share = true`.
- The model turns "deeper, a bit older" into attributes; there's no keyword parsing.
- The desk channel and the Discord call get the profile from the host when they start speaking (see section 4). A
  change takes effect on the next sentence.

## 3. The desk (node app `desk`, `runs_on = "node:desk"`)

**A small Swift helper app**, `Falak Ears.app`, which holds the Microphone permission:
- `AVAudioEngine` with voice processing on (`setVoiceProcessingEnabled(true)`) on the input node, and playback
  through the same engine, so macOS cancels Falak's own voice from the mic on speakers. Report in
  `docs/voice-measurements.md` whether it holds up with AirPods, which bypass voice processing.
- Mic frames (16 kHz mono PCM16) out on stdout; playback frames and commands in on stdin. Line-delimited JSON for
  commands, length-prefixed binary for audio.
- A global push-to-talk hotkey through Carbon `RegisterEventHotKey` (no Accessibility permission). Default ⌥Space;
  hold to talk, or tap to start a conversation. Setting `push_to_talk`.
- Build and sign it the way the old JARVIS Camera app was built (`build()` in `legacy/jarvis/camera.py`: `swiftc`, a
  stamp written before signing, `codesign` with a stable identity setting so macOS keeps the permission across
  rebuilds). The build output goes under `FALAK_NODE_DIR`, never the old JARVIS folders.

**The Python side on the node:**
- **Wake word** with openWakeWord (onnx). A custom "Hey Falak" model has to be trained (openWakeWord's training
  notebook, run on Colab, about an hour). Write the steps in `docs/wake-word.md` for Elijah to run, and load
  `hey_falak.onnx` from `FALAK_NODE_DIR/desk/` when it's there. Until then the pretrained `hey_jarvis` model works as a
  stand-in, and the push-to-talk key always works.
- **Detecting speech** with Silero VAD (onnx), on the echo-cancelled mic. Port the endpointing from
  `legacy/jarvis/ears.py`: a turn ends after `end_silence_ms` (default 700) of silence, and a trailing "and…" or
  "um" waits longer (`GRACE_SECONDS`).
- **Conversation state:** `idle` (only the wake word and the hotkey are listened for), `listening`, `waiting`
  (the host is thinking), `speaking`, and `follow-up` (listening without the wake word for `follow_up_seconds`,
  default 15, after Falak finishes or Elijah stops talking). A soft chime marks `listening` and the end of
  `follow-up`; settings can turn them off.
- **Barge-in:** while `speaking` (or `waiting`), VAD speech that lasts `barge_in_ms` (default 250) on the
  echo-cancelled mic **stops playback on the node at once**, with no round trip, then tells the host where playback
  stopped and starts listening. Port `ECHO_WARMUP` so Falak's first syllable doesn't trigger it.
- Audio goes to the host as it's heard, and the host's audio plays as it arrives. Nothing is written to disk.

**Protocol.** Add binary WebSocket frames for audio, alongside the JSON messages: a small header (stream id,
sequence number, kind) and PCM16. Add JSON messages for the conversation: `VoiceStart`, `VoiceEnd` (the utterance
ended), `PlaybackStopped {stream, played_ms, reason: "barge_in" | "done" | "stop"}`, `SpeakStart`, `SpeakEnd`.
Version the protocol (`VERSION = 2`) and keep version 1 nodes working for everything else.

## 4. The voice channels (host)

`channels/desk.py` is a channel like Discord, with the node's audio as its input:
- An utterance becomes text with `Listener.transcribe`, then a normal turn with `Origin("desk")`.
- **The spoken reply is written as speech, not cleaned up afterwards.** Add one principle to the system prompt
  for voice channels: replies are spoken, so they're short and conversational; anything that needs reading
  (commands, errors, code, links, lists, numbers he'll need later) goes to Discord with a new core tool,
  `falak__send_text(text)`, and the reply says so in a few words. No regex filter over the reply: that's what
  rule 5 forbids.
- **Streaming.** Add an optional `on_text(delta)` to `Brain.run` (the SDK's partial messages). The desk channel
  feeds it to `sentences()` and synthesizes each sentence as soon as it's complete, so the first one plays while the
  rest is written. Text the model writes before a tool call ("one sec, checking your calendar") is spoken too;
  that's the filler, and it stays honest because it only says what Falak is about to do.
- Settings for voice turns: `voice_model` (default from section 0's numbers) and `voice_max_turns`.
- **Interruptions:**
  - The conversation log records what was actually said: the spoken text up to `played_ms`, marked "(interrupted)",
    so the next turn knows where it was cut off.
  - The next utterance becomes the next turn. "Stop" or "never mind" just ends it; the model decides that, not a
    word list.
  - If the turn was still thinking and no tool had run, it's cancelled. If a tool had run, the turn finishes without
    speaking and its result stays in the conversation.
- **Asks work out loud.** A pending ask is read as a question, and "yeah, send it" answers it through the existing
  `answer_ask` path. The Discord ask message still appears, with its buttons.
- Falak only speaks first at the desk (an outbox message, a reminder) when a conversation is open or Elijah was at
  the Mac in the last minute (port `idle_seconds`), and never in quiet hours. Otherwise the outbox goes to Discord
  as now.
- **Latency budget**, measured and logged per turn: end of speech → transcript, → first text, → first audio. The
  target for a no-tool reply is first audio within 2 seconds of Elijah stopping, plus whatever the brain takes
  (section 0's number).

## 5. Discord voice calls (part 2)

- Python can't hear under Discord's end-to-end encryption (DAVE), so a small Node add-on (`@discordjs/voice`, with
  `@snazzah/davey` for DAVE) handles the call. It lives in `channels/discord_voice/`, is started and stopped by the
  host, and talks to it over a local socket: Opus or PCM frames in and out, plus join and leave.
- Elijah's private server has a voice channel. When he joins it, Falak joins too. "Call me" (or `falak__call`)
  sends him a Discord DM with a link to join, since bots can't ring.
- Only Elijah's audio is transcribed, never anyone else's in the channel.
- The same pipeline as the desk: the Listener, the turn with `Origin("discord_call")`, sentences, the Voice and
  barge-in (Discord already cancels echo, so it's VAD only).
- Needs Node 22 (this Mac has 20.20.2: Elijah upgrades it with `brew`), the `Guilds` and `GuildVoiceStates`
  intents, and Connect and Speak permissions. List each step for Elijah; don't change his Discord settings.

## 6. Tests

- `uv run pytest` passes without a mic, speakers, Swift, Node, models or network.
- Fakes for the Listener, the Voice, the Swift helper's stdio and the Node add-on's socket.
- New tests:
  - `sentences()`: cuts at sentence ends, never inside "Dr.", "3.5", "e.g.", a URL or quotes.
  - the voice principle reaches the prompt on `desk` and `discord_call` only; `falak__send_text` sends to Discord.
  - streaming: the first sentence goes to the Voice before the brain finishes.
  - barge-in: playback stopped at 1.2 s logs the spoken prefix marked interrupted; a turn with no tool run is
    cancelled; one with a tool run finishes silently.
  - the node's state machine: wake word → listening → waiting → speaking → follow-up → idle, push-to-talk from
    any state, and barge-in from speaking and waiting.
  - an ask is answered by voice through `answer_ask`.
  - `set_voice` validates, undo restores, and a change applies to the next sentence.
  - protocol v2 audio frames round-trip, and a v1 node still runs the other apps.
  - the layout rule for `jarvis/speech`.
- **Never run against Falak-dev or Falak-node.** Scratch folders for every `jarvis` command and the bench script.
