# M1: Skeleton

**For:** Claude Sonnet, building in Claude Code.

## Goal

Set up the clean foundation for the Falak rehaul: a separate worktree and branch, the old code parked in
`legacy/`, and a new, nearly empty `jarvis` package with settings, logging, a database with migrations, a
small CLI and tests. **No features.** Later milestones build apps, the agent loop, channels and the node on
top of this, so the shape matters more than the amount of code.

## Ground rules for this milestone

- **The live JARVIS must keep working, untouched.**
  - It runs from `~/Library/Application Support/JARVIS/app` with the database
    `~/Library/Application Support/JARVIS/jarvis.db`.
  - Don't write to anything under `~/Library/Application Support/JARVIS/`.
  - Don't run `jarvis schedule install` or any old `jarvis` command.
  - Don't touch `~/Library/LaunchAgents/com.jarvis.*`.
  - Don't commit to `main`.
- **Self-edit and prod mode are on** in the old JARVIS, and they work on `main` in the iCloud repo folder.
  Never work in that folder. Work only in the new worktree.
- **Disk:** the Mac has ~8 GB free, so add no dependencies in M1 beyond `pytest`. Everything else is the
  standard library.
- Stay inside M1. If something seems to need an app, the agent loop, channels, the node or the network,
  leave it for its milestone and note it in your report.

## Steps

### 1. Worktree and branch

From the repo at `~/Library/Mobile Documents/com~apple~CloudDocs/Code/JARVIS`:

```bash
mkdir -p ~/Developer
git worktree add -b rehaul ~/Developer/falak main
```

- Do all of M1 inside `~/Developer/falak`. It's outside iCloud on purpose (virtualenvs and iCloud don't
  mix).
- Use Python **3.12**. It's installed at `/opt/homebrew/bin/python3.12`, and Kokoro, which comes in M8,
  doesn't support 3.14 yet. Pin it with a `.python-version` file containing `3.12`.

### 2. Park the old code

- `git mv jarvis legacy/jarvis` and `git mv tests legacy/tests`.
- `git mv README.md legacy/README.md` and `git mv CHECKLIST.md legacy/CHECKLIST.md`.
- Add `legacy/README-FIRST.md` with one paragraph: this is the old JARVIS, kept read-only as a reference
  for porting. Nothing imports it, and it isn't packaged or tested.
- Leave `PLAN.md`, `ARCHITECTURE.md` and `docs/` where they are.

### 3. New package layout

Create exactly this (an `__init__.py` everywhere, no other placeholder files):

```
jarvis/
  __init__.py          # __version__ = "0.2.0.dev0"; ASSISTANT name is a setting, not hard-coded here
  cli.py               # argparse CLI, see step 7
  core/
    __init__.py
    api.py             # the surface apps may import later; for now only a docstring saying so
    settings.py
    log.py
    db.py
    migrations/
      0001_baseline.sql
  node/__init__.py     # docstring only: device runtime, built in M5
  protocol/__init__.py # docstring only: message types, built in M5
  apps/__init__.py     # docstring only: tool apps, the contract arrives in M2
tests/
  conftest.py
  test_settings.py
  test_db.py
  test_cli.py
  test_layout.py
```

### 4. `pyproject.toml` (replace the old one)

- `name = "jarvis"`, `version = "0.2.0.dev0"`, description "Falak: personal assistant (code name jarvis)".
- `requires-python = ">=3.12,<3.14"`.
- `dependencies = []`; dev extra `pytest>=8`.
- `[project.scripts] jarvis = "jarvis.cli:main"`.
- Hatchling builds only the `jarvis` package. Pytest has `testpaths = ["tests"]`, so `legacy/` is never
  collected.
- Delete the old `uv.lock` and create a fresh one with `uv sync --extra dev`.

### 5. Settings (`jarvis/core/settings.py`)

- A frozen dataclass `Settings` with these fields:
  - `data_dir: Path`: from env `FALAK_DATA_DIR`, default `~/Library/Application Support/Falak-dev`
  - `assistant_name: str = "Falak"`
  - `log_level: str = "INFO"`
  - `apps: dict[str, dict]`: per-app sections from the file; unused until M2
- `load_settings(env: Mapping[str, str] | None = None) -> Settings`:
  - Reads `<data_dir>/settings.toml` with `tomllib` if it exists. Its top-level keys override the defaults,
    and `[apps.<name>]` tables go into `apps`.
  - Unknown top-level keys raise a clear `SettingsError`. Silent typos are how config rot starts.
- `load_secrets(data_dir) -> dict[str, str]`: parses `<data_dir>/.env` (`KEY=value` lines, `#` comments,
  optional quotes) with a few lines of code instead of a dependency.
  - Only the core reads secrets. In M2, apps get only the keys their manifest names.
- Never log secret values.

### 6. Logging (`jarvis/core/log.py`)

- `setup_logging(settings) -> None`: one root configuration.
  - A `RotatingFileHandler` at `<data_dir>/logs/falak.log` (1 MB × 5 files) writing one JSON object per
    line, with time, level, logger and message, plus `extra` fields.
  - A plain-text handler on stderr.
  - Safe to call twice.
- Modules get loggers with `logging.getLogger(__name__)`. No other logging setup anywhere.

### 7. Database (`jarvis/core/db.py`) and migrations

- `connect(settings) -> sqlite3.Connection`:
  - opens `<data_dir>/falak.db`
  - sets WAL mode, `foreign_keys=ON` and `row_factory = sqlite3.Row`
  - runs pending migrations
- **Migrations:** numbered `.sql` files in `jarvis/core/migrations/`, applied in order, each in a
  transaction. Applied versions are recorded in a `schema_migrations(version INTEGER PRIMARY KEY,
  applied_at TEXT)` table. Applying twice is a no-op.
- **`0001_baseline.sql`** is the old JARVIS schema, so a fresh database and a copied one have the same
  shape.
  - Get it read-only with
    `sqlite3 -readonly "$HOME/Library/Application Support/JARVIS/jarvis.db" .schema`.
  - Turn every `CREATE TABLE` / `CREATE INDEX` into the `IF NOT EXISTS` form.
  - Skip `sqlite_` internal tables.
  - Commit only the schema, never any data.
- **`import_legacy_db(settings, source: Path) -> dict`:**
  - Copies the live database into `<data_dir>/falak.db` using `sqlite3`'s backup API, with the source
    opened read-only (`file:...?mode=ro` URI). That's safe while the old JARVIS is running.
  - Then runs migrations and returns row counts per table.
  - Refuses to overwrite an existing `falak.db` unless `overwrite=True`.

### 8. CLI (`jarvis/cli.py`)

- `jarvis --version` prints `jarvis 0.2.0.dev0 (Falak)`, using the configured assistant name.
- `jarvis dev info` prints the data folder, database path, applied migration versions, assistant name and
  log path. It shows no secrets, only the names of keys found in `.env`.
- `jarvis dev import-db [--source PATH] [--overwrite]`:
  - The source defaults to the live JARVIS database.
  - Prints the row counts.
  - Exits non-zero, with a plain message, if `falak.db` already exists and `--overwrite` wasn't passed.
- Every command calls `load_settings` and `setup_logging` once at the start. Keep `cli.py` thin: it parses
  arguments and calls core functions.

### 9. Repo `CLAUDE.md` (replace any existing one at the worktree root)

Keep it under 40 lines:
- what Falak is (one line)
- read `ARCHITECTURE.md` before changing code, and the milestone brief before starting work
- commands: `uv sync --extra dev`, `uv run pytest`, `uv run jarvis dev info`
- the live-system rules from "Ground rules" above, as bullets
- "Don't import from `legacy/`; read it to port behavior on purpose."

### 10. Tests

- **`conftest.py`:** a fixture that points `FALAK_DATA_DIR` at a `tmp_path`, so tests never touch a real
  data folder.
- **`test_settings.py`:**
  - defaults
  - `settings.toml` overrides
  - an unknown key raises `SettingsError`
  - the `.env` parser handles comments, quotes and blank lines
- **`test_db.py`:**
  - a fresh database gets every baseline table
  - migrations are idempotent
  - a second test migration applies once
  - `import_legacy_db` copies from a small temp source database built in the test, refuses to overwrite,
    and overwrites with the flag
- **`test_cli.py`:**
  - `--version` output
  - `dev info` runs against the temp data folder
  - `dev import-db` exits non-zero when the target exists
- **`test_layout.py`:** the architecture rules as tests, using an AST scan of imports under `jarvis/`:
  - `jarvis.core` never imports `jarvis.node`, `jarvis.apps` or `legacy`
  - `jarvis.node` never imports `jarvis.core`
  - nothing imports `legacy`
  - no module under `jarvis/` is over 400 lines
