# M6: The scheduler, and the first apps that act on their own

**For:** Claude Sonnet, building in Claude Code, in the `~/Developer/falak` worktree on branch `rehaul`.
**Read first:** `CLAUDE.md`, `ARCHITECTURE.md`, then "Scheduler (replaces the tick)" and "Tools are apps" in
`PLAN.md`. Build on the M4 host (`jarvis/host.py`) and the M5 contract package. Don't add a second loop,
a second way to send messages or a second permission check.

## Goal

Until now Falak only speaks when spoken to. M6 lets apps run **jobs**: scheduled work that runs inside
`jarvis serve` and can message Elijah first. It replaces the old 5-minute `jarvis tick`, which ran 17
unrelated steps in a row, mostly doing nothing (see "Why the tick goes" below).

With the scheduler in place, port the first apps that need it:
- **reminders:** "remind me at 3 to call the bank" arrives at 3:00, not up to 5 minutes later
- **school:** Canvas sync, deadlines, and deadline nudges
- **checkins:** the morning brief and the evening check-in
- **journal:** the nightly write-up of the day

## Out of scope

Leave these for later and note anything you needed from them:
- **mail watch:** it moves to M7 with the mail app, which reads Mail on the Mac node
- **the heartbeat** ("anything Elijah should know right now?"). It was mostly noise in the old tick. It gets
  rebuilt later as reacting to changes, on top of these jobs.
- **watches:** 1,131 of 1,133 old runs checked nothing. Leave them out.
- location, timers and alarms through Siri, music (all M7)
- spoken delivery at the desk (M8)
- Pushover or any other urgent channel. "Urgent" is just a Discord message for now.
- a launchd job for `jarvis serve` (M9)
- any UI

**Why the tick goes** (from 2,045 old ticks, Oct 15–26):
- A fresh `uv run` process every 5 minutes. The order of the steps lived only in comments.
- Steps that call Claude ran before delivery steps, so a slow model call held up reminders and alerts.
- Canvas and Mail failed about 140 times, mostly just after the Mac woke up, and each failure was logged as
  an error.
- Without Telegram, drafts, reminders and ideas were skipped entirely.

## 1. Jobs in the manifest

Add `[[jobs]]` to the manifest. This replaces the "'jobs' is not valid yet (M6 adds it)" error.

```toml
[[jobs]]
name = "deliver"
description = "Send reminders that have come due."
handler = "deliver_due"   # handler(ctx, run: JobRun) -> JobResult
kind = "deliver"          # deliver | sync | think
every = "15m"             # a fallback interval; the job also wakes itself (see wake_at)
quiet = "ignore"          # in quiet hours: ignore (run and send), hold (run, send later) or skip (don't run)
needs = []                # "network": skip quietly while offline
timeout_s = 30
```

- **Triggers.** A job has `every` (`"30s"`, `"15m"`, `"6h"`; at least 30 s), or `at` (local times, a string
  or a list, e.g. `["07:00", "21:00"]`), or both. One of them is required.
- **Waking itself.** A job can ask to run sooner:
  - `JobResult.wake_at`: run again at this time. This is how a reminder fires exactly when due: the deliver
    job returns the next due time.
  - `ctx.wake("<job>")` from any handler of the same app: run that job now, e.g. right after `remind_me`
    saves a reminder.
  - Triggers between different apps (events) come later. Don't build an event bus.
- **Validation** (in `jarvis.contract.manifest`, with contract tests):
  - name is snake_case and unique within the app
  - the handler exists
  - `kind`, `quiet` and `needs` take only the values above
  - intervals parse, `at` times are valid `HH:MM`, and `timeout_s` is 1–600
  - a `think` job may not use `quiet = "ignore"`

**Additions to `jarvis.contract.api`** (apps still import nothing else from the core):

```python
@dataclass(frozen=True)
class JobRun:
    now: datetime            # timezone-aware, in Elijah's timezone
    last_ok_at: datetime | None
    reason: str              # "every", "at", "wake", "manual" or "catch-up"
    quiet: bool              # inside quiet hours right now

@dataclass(frozen=True)
class Think:
    prompt: str              # what the thinking turn is about, with the data it needs
    deliver: bool = True     # send the reply to Elijah; False for jobs that only use tools (the journal)
    untrusted: bool = False  # the prompt quotes someone else's words (assignment titles, mail)

@dataclass(frozen=True)
class JobResult:
    summary: str                    # one line for the job log: "sent 2", "17 deadlines, 1 new"
    messages: tuple[str, ...] = ()  # sent to Elijah exactly as written
    think: Think | None = None      # ask the host for a thinking turn (counts against the budget)
    wake_at: datetime | None = None
```

- `AppContext` gains `now()` (aware, in Elijah's timezone), `tz`, and `wake(job)`. `wake` is a no-op
  outside `jarvis serve`.
- Jobs run only for host apps in M6. A `[[jobs]]` entry in an app with `runs_on = "node:*"` is a manifest
  error for now.

## 2. The scheduler: `jarvis/core/scheduler.py`

One asyncio task inside `Host.run`, next to the session sweep.

- **Timing:**
  - It works out the next due time over all jobs and sleeps until then, or until a `wake`.
  - It never sleeps more than 30 s at a time and always compares against the wall clock, so after the Mac
    sleeps it notices at once that jobs are overdue.
  - Missed runs collapse. An `every` job that missed 40 intervals runs once (`reason = "catch-up"`).
  - An `at` time missed by up to 2 hours runs once on wake. Missed by more, it's recorded as "missed" and
    skipped. Make that limit a core setting, `catch_up_minutes = 120`.
- **Running:**
  - Each run executes in a worker thread with its own SQLite connection (WAL, `busy_timeout = 5000`).
    Don't use the shared `reg.conn`, so a slow Canvas fetch never waits on a turn and a turn never waits
    on Canvas.
  - Set `busy_timeout` on the main connection too.
  - At most one run of a job at a time, and at most 4 job threads overall.
- **Timeouts:** a run past `timeout_s` is recorded as failed. Its thread can't be killed, so that job
  doesn't start again until the thread has actually ended. Log it once if that takes long.
- **Needs:** `network` means a cheap online check: a TCP connect to `1.1.1.1:443` with a 2 s timeout,
  cached for 30 s.
  - While offline, the run is recorded as `skipped: offline`. It's not a failure and nobody is told.
  - Retry at the next trigger, or 1 minute after the network comes back, whichever is first.
- **Failures:** retry with backoff (1, 2, 5, 10, then every 30 minutes) until the next normal trigger.
  - After **3 failures in a row while online**, Elijah gets one message: "Canvas sync keeps failing (401
    Unauthorized). I'll keep trying and tell you when it works." When it recovers, one line: "Canvas sync is
    working again."
  - No more messages in between.
- **Quiet hours:** core setting `quiet_hours = "23-7"`; an empty string turns them off. Port
  `parse_quiet_hours` and `in_quiet_hours` from `legacy/jarvis/alerts.py` into `core/timeutil.py`.
  - `ignore` runs and sends.
  - `hold` runs. Its messages wait in the outbox until quiet hours end.
  - `skip` doesn't run.
- **Timezone:** core setting `timezone = "America/Los_Angeles"`, checked with `zoneinfo` when the settings
  load. Add a line to the turn context with the local time and weekday, if it isn't there already, so
  "remind me at 3" means 3 PM Seattle time.
- **The record:** migration `0005` adds two tables.
  - `jobs(app, name, next_run_at, last_run_at, last_ok_at, last_status, last_error, last_ms, failures,
    reported_at, PRIMARY KEY(app, name))`. On startup the scheduler loads its state from here, so a restart
    neither re-runs nor forgets anything.
  - `job_runs(id, app, name, started_at, ms, status, reason, summary, error)`, pruned to 14 days by the
    scheduler itself.

## 3. Delivery: one outbox, one way out

Everything Falak says first goes through the **outbox**, a core table `outbox(id, text, source,
created_at, not_before, sent_at, attempts, last_error)` in migration `0005`.

- `Host.notify(text, source)` adds a row and wakes the sender. Job messages, failure reports and
  thinking-turn replies all use it.
- **The sender** is one asyncio task. It sends due rows, oldest first, through the notify channel:
  - That's a core setting `notify_channel = "discord"`, falling back to the first channel that's running.
  - It uses the M4 `channel.send(text)` with no `reply_to`, which DMs Elijah.
  - On failure it keeps the row and retries with backoff: 5 s, 15 s, 1 min, then every 2 minutes.
- **Late messages:** a row that goes out more than 2 minutes after it was created gets a line:
  "(held: Discord was unreachable at 3:05 PM)". It's held until `not_before` in quiet hours.
- **Every sent message is added to the conversation** as an assistant message, so a reply like "done" or
  "how was it?" has context.
- With no channel configured at all (for example `jarvis jobs run` from the CLI), messages are printed and
  stay in the outbox until `serve` sends them. They're never dropped.

## 4. Thinking jobs and the budget

A job that returns `JobResult(think=Think(...))` asks for a **thinking turn**.

- It's the same agent loop as a chat turn (`loop.handle_message`, or a sibling that shares its body; don't
  copy it). It has the same tools and the same policy, and runs under the host's `_turn_lock`.
  - Its origin is `Origin("job:<app>.<job>", outside_content=think.untrusted)`. A job is not one of
    Elijah's own channels, so `answer_ask` refuses there.
  - The turn's text goes into the `turns` table with that channel. The prompt isn't stored as a user
    message.
- **Waiting behind chat:** user messages go first. A thinking turn waits while a chat turn or another
  thinking turn is running, and never pre-empts one.
- **Delivery:** if `deliver` is set, the reply goes to the outbox. A reply of exactly `(nothing)` sends
  nothing. Say this in the thinking-turn system addendum, so "nothing worth saying" is possible.
- **The budget** is a core setting, `thinking_runs_per_day = 12`, counted from `turns` where the channel
  starts with `job:`, per local day.
  - Over budget, the run is recorded as `skipped: budget`, logged once a day, and Elijah isn't told.
  - Chat turns never count against it.
- Thinking turns get a 2-line addendum to the system prompt: this is Falak speaking first, keep it short,
  and `(nothing)` is allowed.

## 6. The CLI

- `jarvis jobs`: one line per job, with app.name, trigger, last run (status, how long ago, ms), next run,
  and failures. It reads the `jobs` table, so it works while `serve` is running.
- `jarvis jobs run <app>.<job>`: runs one job now, in this process.
  - It uses the same code path with `reason = "manual"`, ignoring quiet hours and the `at` time but not
    the budget.
  - Messages go to the outbox. With `serve` running they're sent within seconds. Without it they're printed
    and wait.
  - A thinking job runs its turn here with the real brain.
- `jarvis outbox`: unsent and recent messages.
- `jarvis dev info` shows the job count and unsent outbox rows.

## 7. Tests

The scheduler takes a clock and a sleep function, so no test waits on real time.
- **Manifest:** every new key validates, and every bad value has its error. Node apps can't have jobs yet.
- **Scheduler:**
  - `every` and `at` compute the right next run across days, DST changes and the timezone setting
  - missed runs collapse into one catch-up
  - an `at` time missed past `catch_up_minutes` is recorded as missed
  - `wake_at` and `ctx.wake` run a job early
  - one run per job at a time; a timed-out run blocks the next until its thread ends
  - offline skips record no failure and send nothing
  - three failures while online send exactly one message, and recovery sends one
  - state survives a restart: same next run, no repeat
  - `job_runs` pruning
- **Quiet hours:** `ignore`, `hold` and `skip`, including a window that crosses midnight.
- **Outbox:**
  - send order
  - retry after a failing channel
  - the "held" note after 2 minutes
  - `not_before`
  - messages are added to the conversation
  - nothing is dropped without a channel
- **Thinking turns** (with `ScriptedBrain`):
  - they wait behind a chat turn
  - the origin is `job:…`, and `answer_ask` refuses there
  - `untrusted` flips outside content
  - `(nothing)` sends nothing
  - the budget skips the 13th run and leaves chat alone
- **Apps:**
  - reminders: claim, the late note, the next `wake_at`, undo, past and far-future times rejected, and the
    migration marking old rows
  - school: the ported Canvas parsers with fixtures (no network), nudges sent once, and sync over a fake
    HTTP opener
  - checkins: once a day, the `morning_latest` catch-up
  - journal: material built from a seeded day, and `save_entry` undo
- Every earlier test still passes, and `tests/test_layout.py` covers the new modules.
