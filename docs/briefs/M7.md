## 1. Apps calling apps: `ctx.call`

### Manifest
- `[app] uses = ["school", "reminders"]`: the apps this one may call. Calling anything else is a bug and raises.
- On an action: `share = true` lets apps that list this one in `uses` call it. Only `effect = "read"` actions
  may be shared; the manifest loader rejects `share = true` on anything else.
- On an action: `tool = false` keeps it out of the model's tools. Use it for shared actions that only make sense
  to other apps. Default `true`.

### Contract
```python
ctx.call(app: str, action: str, **args) -> Result
```
- Goes through the same dispatch as every other handler (`core/dispatch.py`), so it works for host and node
  apps. Validates `args` against the action's input schema.
- Raises `AppUnavailable(ActionError)` when the app isn't installed or enabled, or its node isn't connected.
  Callers treat that as "not available" the way `_rows(...) is None` does today.
- Works from a job's worker thread (its own connection) and from an action handler. A shared call runs the
  target handler with a context on the **caller's** connection.
- Not written to `action_log`: it's not something Elijah or the model did. Log it at debug in the caller's
  app log.
- No confirmation path: shared actions are reads.

### Move the cross-table reads onto it
- **school:** shared action `deadlines_between(start, end)` → `data = {"deadlines": [{key, course, title, due,
  done, kind, url}]}`, `due` as ISO 8601 with offset, `done` true for hand-done, submitted or graded. `tool =
  false`. The model keeps `upcoming`.
- **reminders:** shared `list_reminders` (already read; add `data`), and new shared `sent_between(start, end)`,
  `tool = false`.
- **journal:** shared `read_journal` (add `data`), and new shared `latest_entry()`, `tool = false`.
- Rewrite `checkins/sources.py` and `journal/material.py` to use `ctx.call`. Keep their output text the same so
  the existing tests still describe the behavior.
- Add a test that scans every app's `.py` and `.sql` files and fails if one names another app's tables
  (`<other app>_` after `FROM`, `JOIN`, `INTO`, `UPDATE` or `TABLE`). Core tables (`chat_log`, `action_log`) are
  reached only through `ctx` methods, so the scan covers them too, except `contract/api.py`.

## 2. A thinking job learns how its turn went

- Add `on_done: str | None = None` to `Think`: the name of a handler in the same app,
  `handler(ctx, run: JobRun, outcome: str) -> None`.
- The scheduler calls it in a worker thread after the thinking turn, only when the turn didn't fail or get
  skipped. `outcome` is what `Host.think` returns today: `"replied"`, `"nothing to say"` or
  `"thought, not sent"`.
- A failed or skipped turn doesn't call it, so the job's normal failure handling retries.
- **checkins:** move the `checkins_sent` insert into `on_done`. Before the turn, only check whether today's row
  exists. A morning check-in whose turn fails is retried on the job's backoff, up to `morning_latest`. A manual
  run still doesn't record.
- Test it: a brain that raises on the first call and answers on the second gives exactly one check-in, sent
  on the retry.

## 4. web (host)

Port `legacy/jarvis/websearch.py` and the fetch half of `legacy/jarvis/web.py`.

- **search(query, n = 5)**, read, `untrusted_output = true`.
  - Brave Search by default, Google Programmable Search as the option. Settings `provider`, `daily_limit = 40`.
    Secrets `SEARCH_API_KEY`, `SEARCH_ENGINE_ID` (Google only). Elijah adds them to `Falak-dev/.env`.
  - Clean the query first: strip email addresses and links, collapse whitespace, cap the length.
  - Count today's searches in `web_searches` and refuse past the limit in plain words.
  - Every failure comes back as one plain sentence (no key, no network, key refused, rate limit).
- **read_page(url)**, read, `untrusted_output = true`.
  - `urllib.request`, 20 s timeout, at most 2 MB read, `text/html` and `text/plain` only.
  - Readable text (drop scripts, styles, nav) with `html.parser`, capped at 15,000 characters, plus up to 60
    links.
  - Port `check_url` and `blocked_site`: http(s) only, no addresses on this Mac or the local network (check
    every redirect hop and the resolved IP, not just the name), no banking or payment sites. Setting
    `blocklist` for extra domains.
  - Pages that need JavaScript come back thin. Say so ("the page needs a browser to show its text") instead of
    pretending.
- **Leaving the Mac after reading outside content.** A search query or a URL can carry data out. Add
  `sends_data = true` to the manifest for actions whose arguments leave the device, set it on both web actions,
  and change `needs_confirmation` (still the only place the decision is made) so a `sends_data` action asks
  when `origin.outside_content` is true. Ordinary "look this up" turns run without asking. A turn that has
  read a web page, a screen or a check-in's assignment titles asks before the next search or fetch.
- Context: none.

## 5. music (Mac node, `runs_on = "node:music"`)

Port `legacy/jarvis/spotify.py`, `applemusic.py` and `media.py`.

- **play(query, kind = "any")**, local. `kind` is song, artist, playlist or any. Spotify Web API first (search,
  best match, play on the active device or the first open one). Apple Music when Spotify is unavailable, errors
  or has no match: a library playlist by that name, else a library song, else the top catalog song through
  the public iTunes Search API. Report only what really started.
- **control(op, value?)**, local. The fixed op list from `media.py` (pause, resume, skip, back, seek,
  volume set/up/down/mute, shuffle, repeat, queue, like). Spotify API, then AppleScript in whichever app is open,
  then the system media keys.
- **now_playing()**, read.
- Secrets in `Falak-node/.env`: `SPOTIFY_CLIENT_ID`, optional `SPOTIFY_CLIENT_SECRET`; settings `market = "US"`,
  `redirect_uri = "http://127.0.0.1:8888/callback"`.
- **Tokens:** the refresh token lives in the Keychain under its **own** service, `Falak Spotify`. Never read or
  write the old `JARVIS Spotify` item: Spotify rotates refresh tokens, so sharing one would sign the live
  JARVIS out. Add `jarvis node music-login`, a PKCE sign-in Elijah runs once, storing Falak's token. Secrets go
  to `security` on stdin, never in argv or logs (as the legacy `Keychain` does).
- AppleScript gets the query and links as `on run argv` arguments, never pasted into script text. Missing
  macOS permissions come back as the plain sentence the legacy `explain` gives.
- Leave out `SPOTIFY_APP_FALLBACK` (driving the desktop app's UI).

## 6. messages (Mac node, `runs_on = "node:messages"`)

Port the texts, calls and contacts parts of `legacy/jarvis/siri.py`.

- **send_text(to, body)**, outbound. **call(to)**, outbound (FaceTime audio or iPhone through a `tel:` link,
  as the legacy code does). Both ask every time, and the ask is bound to the exact recipient and text by the
  existing confirmation code. Don't add a second approval path.
- **find_contact(name)**, read: names and labelled numbers from Contacts.
- `to` is a name or a number. Port `normalize_number`. A name is resolved through Contacts on the node; no
  match or more than one is refused with the names found, so Falak asks instead of guessing.

- The node has no database. Saved facts like "Mom's number" stay in memory; the model can recall one and pass
  the number.
