# M8: Work apps

**For:** Claude Sonnet, building in Claude Code, in the `~/Developer/falak` worktree on branch `rehaul`.
**Read first:** `CLAUDE.md`, `ARCHITECTURE.md`, then "Confirmations, redesigned" and "Tools are apps" in `PLAN.md`.
Build on the M2 contract, the M5 node, the M6 scheduler and M7's `ctx.call`. Don't add a second way to run a
handler, a second permission check or a second way to send messages.

## Goal

Falak works on code with Elijah without asking about every `ls`. In the old JARVIS, 186 of 192 approval requests
in two weeks were terminal commands, and he said yes to almost all of them. M8 builds:

1. **`ctx.notify` from a node.** A node app can tell Elijah something on its own (a job finished, a task is done),
   through the host's outbox, without losing it when the link drops.
2. **A `plan` effect.** The third kind of ask in `PLAN.md` ("plans you want to steer") becomes an effect, so
   starting a task asks once, with the plan in the question.
3. **terminal** (Mac node): run commands graded by risk, safe ones in a sandbox without asking; background jobs;
   Claude Code tasks in a project folder.
4. **projects** (host): Elijah's projects and repos, carried over from the old database.
5. **`docs/parity.md`**: the everyday-use checklist that says whether Falak can replace the old JARVIS.

## 1. `ctx.notify` from any app

```python
ctx.notify(text: str) -> None
```
- On the host, it's `Host.notify(text, source=f"app:{app}")`: a row in `outbox`, sent by the one sender task.
- On a node, the runtime writes the message to `FALAK_NODE_DIR/outbox/<uuid>.json` first, then sends it to the
  host. Add two protocol messages:
  - `Event {id: str, app: str, text: str}`, node to host.
  - `EventAck {id: str}`, host to node, once the outbox row is committed. The node deletes the file on ack.
- On connect (after `Welcome`), the node resends every unacked file, oldest first.
- The host inserts with the event id as a dedupe key: add a nullable unique `dedupe_key` column to `outbox`
  (core migration `0006`), `INSERT OR IGNORE`, and ack either way. A resent event is never sent to Elijah twice.
- The host refuses an `Event` for an app the node didn't announce in `Hello`, and caps `text` at 4,000 characters.
- Only for things Falak says first, as `ARCHITECTURE.md` says of the outbox. Not for action results.

## 3. terminal (Mac node, `runs_on = "node:terminal"`)

Port `legacy/jarvis/terminal.py` (grading, running, auditing), `jobs.py`, the sandbox half of `introspect.py`,
`agent.py`, `tasks.py` and `repos.py`'s `discover`. Commands, jobs and tasks are one app because they share the
grading and the sandbox, and an app can't import another app. Split it into modules (`grade.py`, `sandbox.py`,
`run.py`, `jobs.py`, `tasks.py`, `repos.py`), each well under 400 lines.

### Folders
- Setting `work_roots`, default `"~/Developer, ~/local_dev, ~/Projects, ~/Documents/code, ~/Desktop"`. A command's
  project root is the git repo containing its `cwd` if that repo is under a work root, else the `cwd` itself if it
  is under a work root. Outside the work roots, nothing is writable without asking.
- Setting `read_only`, default: this checkout (`~/Developer/falak` and its worktrees), the iCloud `Code/JARVIS`
  folder, `~/Library/Application Support/JARVIS`, `Falak-dev` and `Falak-node`. Inside these, writes always ask
  and tasks run read-only. Self-edit stays off.
- Secrets are refused whatever the grade, and no sandbox can read them: port `is_secret`, `is_secret_path`,
  `deny_secrets` and `redact`.

### Grading
Port `classify` and its tables, then fix the grades the real history shows were wrong. Read
`~/Library/Application Support/JARVIS/commands.jsonl` (read-only: never write under that folder) and make every
commonly approved command that is safe grade low or medium, each with a test. At least:
- `git -C <path> <read subcommand>` is low. (43 approvals, because the subcommand had to come first.) `-C` only;
  `-c` and `--git-dir` stay refused.
- `open -a <App>`, `open <file or folder>` (not secrets) run without asking; `open <URL>` asks.
- `pgrep`, `ps`, `lsof -i`/`-p`, `which`, `screen -ls`, `tail -n N <file>` (no follow) stay or become low.
- `rm` of files or folders inside the project root never runs `rm`: the handler moves them to `~/.Trash`
  (a unique name if one exists) and returns an undo that moves them back. Outside the root, or inside `.git`, asks.

Low runs in the no-writes, no-network sandbox, medium in the write-only-inside-the-root sandbox, both with no shell,
the scrubbed environment and a timeout, output redacted and capped at 6,000 characters. High and critical (push,
reset, sudo, installs elsewhere, anything that reaches other people, anything not recognised) ask. Shell syntax is
refused, never interpreted.

### Actions
- **run(command, cwd = "", background = false)**, `local`, `untrusted_output = true`, with undo (only Trash moves
  have anything to undo). Grades, then runs low and medium. A command that needs a yes isn't run: the result says,
  for the model, "This needs Elijah's OK (<reason>): use run_with_ok with a short why." `background = true` starts
  it as a job (below), sandboxed the same way.
- **run_with_ok(command, cwd, why, background = false)**, `irreversible`, confirm "Run `<command>` in <folder>?
  It's to <why>." Runs as Elijah: no sandbox, still no shell, scrubbed environment, secrets still refused, 120 s
  unless background.
- **jobs()**, read: running and recent jobs, one line each.
- **job_log(id, lines = 40)**, read, `untrusted_output = true`.
- **stop_job(id)**, local.
- **start_task(goal, folder, plan)**, `plan`, confirm "Start a task in <folder>: <plan>. Go?"
- **task_status(id = 0)**, read, `untrusted_output = true`: state, runs, minutes, the last 10 steps (0 = newest).
- **stop_task(id = 0)**, local.
- **find_repos()**, read, `share = true`, `tool = false`: `data = {"repos": [path, …]}` under the work roots
  (legacy `discover`).
- **repo_state(path)**, read, `share = true`: branch, last commit (subject, date), uncommitted file count,
  ahead/behind upstream if known.
- Each action's `timeout_s` must cover its own work: 130 s for `run` and `run_with_ok`, a few seconds for the rest.

### Jobs
- Port `jobs.py`: detached, own session, output to `FALAK_NODE_DIR/terminal/jobs/<id>/job.log`, the `-I`
  wrapper that records the exit code, states running, exited and lost.
- A watcher thread in the app (started by the node runtime when the app loads, stopped with it) checks every 15
  seconds while a job runs, and does nothing while none does. It calls `ctx.notify` once when a job ends (with
  the last 3 log lines, and the "it was waiting for typed input" note), and once if it prints nothing for
  `job_stall_minutes` (default 20). Finished jobs older than 14 days are removed.

### Tasks: Claude Code sessions in a project
- Run with `claude_agent_sdk.query` on the node, the folder as `cwd`, built-in tools `Read, Edit, Write, Glob,
  Grep, Bash, TodoWrite` only, `setting_sources=[]`. The folder's `CLAUDE.md`, if any, goes into the first prompt
  as data. Settings `model` (default `"sonnet"`), `max_turns` per run (60), `max_minutes` (60), `max_runs` (6).
- **Every tool call is graded in-process** (a `PreToolUse` hook or `can_use_tool`, whichever the SDK version in
  `uv.lock` supports cleanly), porting `agent.decide`: reads anywhere but secrets; edits inside the folder (never
  `.git`, never in a read-only folder); Bash by `classify`: low and medium run, everything else is **denied**,
  with the reason "needs Elijah's yes: don't do it; list it under NEEDS YES in your final message." Any error in
  the decision denies.
- **The whole `claude` process is sandboxed** as in `agent.claude_sandbox`: writes only to the folder (not in
  read-only mode), the task's state folder, Claude Code's own files, package caches and temp; secrets unreadable
  except the keychain entry Claude Code signs in with. Use `cli_path` pointing at a small generated wrapper
  (`/usr/bin/sandbox-exec -p <profile> <real claude> "$@"`).
- Tasks keep their Claude Code session (no `no-session-persistence`, unlike chat) so a restart resumes them.
  Store state in `FALAK_NODE_DIR/terminal/tasks/<id>/task.json`: goal, folder, plan, status (queued, running,
  done, failed, stopped), session id, runs, active seconds, steps (last 60), summary, needs-yes list.
- One task runs at a time (8 GB of RAM); more wait in the queue. On node start, a `running` task goes back to
  the queue with a resume note.
- Port the rules text (`AGENT_RULES`), in Falak's name: one plain command per Bash call, scratch folder, no
  typed input, untrusted content, `TELL ELIJAH:` lines (sent with `ctx.notify`, at most 3 per task), and the
  final `STATUS: done` or `STATUS: stuck` line plus a `NEEDS YES:` list of commands it wanted but wasn't allowed.
- When a task ends, one `ctx.notify`: "✅ <short goal>: <summary>" or "❌ …", then any NEEDS YES commands, each on
  its own line, so Elijah can say "go ahead and push" and Falak calls `run_with_ok` (which asks with the exact
  command). Budgets running out end it as failed, saying which one.
- Mention in `ARCHITECTURE.md` (Devices) that tasks are the one place the node runs Claude, and why: the files
  are on the node.
